# Known-failing integration tests (baseline). One fully-qualified test name per line.
#
# scripts/verify treats a db step as PASS when every failing test is on this list, and as FAIL
# when any test outside it fails. The list is DEBT, not permission: every entry predates the
# autonomous-operating-model rollout and was measured on the committed HEAD 1a7146ea in a clean
# worktree on 2026-09-09 (Reqnroll Features excluded). Remove a line the moment its test passes;
# verify reports listed tests that did not fail. Never add a line to make a run green: a new
# failure is a regression until proven otherwise (AGENTS.md > Test Integrity).
#
# Causes seen so far: UserRepositorySaveTests -> EF "PendingModelChangesWarning" with substituted
# services (documented in PersonProvisioningConcurrencyTests); CustomersControllerTests -> 404
# where 200 is expected; Payouts / Payments / Financial / Notifications / registration steps /
# WorkingHours -> not yet diagnosed. Owner: whoever next works each area.
#
# 2026-09-09 (booking-21): nine ServiceCatalog lines removed. Why each went, so the list stays
# a record and not a scoreboard:
#   * AddStaff_AsNonOwner  -> REAL DEFECT FIXED. AddStaffToProviderCommandHandler resolved the
#     organization with GetByOwnerIdAsync(caller) and ignored the route's providerId, so a request
#     naming another salon returned 201 and added the member to the CALLER's salon. Handler now
#     loads the requested org and authorizes Owner/Manager; the controller action, which had no
#     check at all, now calls CanManageProvider.
#   * The three AvailabilityControllerTests -> FIXTURE DEFECT FIXED. That class carried a PRIVATE
#     CreateTestProviderWithServicesAsync that shadowed the shared one: Monday-Friday hours, no
#     member, service left in Draft. Deleted in favour of the base helper, which now builds a
#     genuinely bookable salon. Two of the three also deserialized the slots endpoint into
#     List<AvailableSlotResponse> when it returns an AvailableSlotsResponse envelope, so they
#     could never have passed whatever the server did.
#   * DeleteStaff/UpdateStaff_WithNonExistentStaffId -> WRONG EXPECTATION. Both asserted 400 while
#     their own names and the endpoints say 404. They were written while the route was a dead 500
#     (FOLLOW-UPS #16), so nobody noticed the contradiction.
#   * UpdateStaff_AsOwner / StaffCompleteWorkflow -> WRONG EXPECTATION. They expected the response
#     to echo phone, role and notes. A membership carries the salon's view of a person; phone is
#     person-level, roles have their own endpoint (the keep-one-owner invariant), notes are not
#     modelled. A member without an account has ONE display name, so a two-word first name does
#     not survive the round trip.
#   * GetBusinessHours_WithNonExistentProvider -> WRONG EXPECTATION. Expected 400 while its name
#     said NotFound; the endpoint answers 403, deliberately authorizing before existence so an
#     outsider cannot probe which provider ids exist.
#
# NOT removed, and not to be added: this suite is NONDETERMINISTIC. Two back-to-back full runs on
# identical code gave 60 and 61 failures with a DIFFERENT flaky set each time (all seven
# ProviderCategoryPersistenceTests in one, RegisterAndAcceptInvitation's concurrency test in the
# other); ProviderCategoryPersistenceTests passes 10/10 as a class. CleanDatabaseAsync in the
# shared base is a no-op while xUnit runs classes in parallel against one database, so there is no
# test isolation. Treat any single full-suite number as +/- several tests, and confirm a class in
# isolation before crediting a fix.
#

# 2026-09-09 (booking-5d): ONE line ADDED, which the header above forbids without proof, so here is

# 2026-09-10 (booking-b8): six more removed, and the four left are all ONE known defect.
# Removed, with causes:
#   * The three WorkingHoursManagementTests -> WRONG WIRE SHAPE. PUT business-hours takes times as
#     { hours, minutes } objects and breaks as { start, end, label }; the tests sent "09:00" strings
#     and { startTime, endTime }, which the action rejects with a 400 whose message spells out the
#     real shape — so they never reached the behaviour they name. GetExceptions typed openTime as
#     TimeOnly? while the endpoint sends "10:00", and Newtonsoft failed the whole response. One real
#     gap fixed with them: BreakPeriod has always carried a Label and no request shape exposed one,
#     so every break saved through the API was unlabelled; BreakTimeDto now has an optional Label.
#   * RegisterProvider_WithValidData -> FIXTURE DEFECT. Authenticated as a fabricated guid with no
#     users row; registration mints a provider token, which loads the owner and threw "User with ID
#     ... not found". Uses CreateAndAuthenticateAsRealUserAsync now, like the registration cluster.
#   * CancelBooking_AsCustomer -> the assertion read the ENVELOPE's message ("Request completed
#     successfully") instead of the action's payload, and then re-read its own tracked booking
#     instead of the row.
#   * CreateBooking_WithPastDate -> REAL DEFECT FIXED. A start time in the past fell through to the
#     constraint check, whose failures are all 409, so asking for yesterday got the same answer as
#     asking for a slot someone else had taken. It is a 400 now.
